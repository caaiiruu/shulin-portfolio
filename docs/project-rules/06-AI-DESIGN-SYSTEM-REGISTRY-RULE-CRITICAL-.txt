AI DESIGN SYSTEM REGISTRY RULE (CRITICAL)
PURPOSE

The portfolio design system must be understandable by:

Humans
AI Agents
Cursor
Claude
GPT
Future contributors

The goal is not only to build reusable UI.

The goal is to create a deterministic design system knowledge layer that allows AI to identify:

ownership
dependencies
usage scope
figma mapping
modification boundaries

before making changes.

01 — REGISTRY-FIRST RULE

Before creating a Design System showcase page:

Build the registry layer first.

Order:

Figma
↓
Tokens
↓
Components
↓
Registry
↓
Documentation
↓
Design System Explorer

Do not build visual documentation before the registry exists.

02 — COMPONENT REGISTRY RULE

Every approved reusable component must have a registry entry.

Required fields:

Component:
Status:
React Source:
CSS Owner:
Token Dependencies:
Variants:
Usage Scope:
Figma Source:
Code Connect Status:
Allowed Modifications:
Forbidden Modifications:

Example:

Component:
ProjectCard

Status:
Live / Current Production

React Source:
src/components/ProjectCard.tsx

CSS Owner:
src/styles/components/project-card.css

Variants:
Row
Grid

Usage Scope:
Work Page
Results Page

Allowed Modifications:
Variant Extension
Prop Extension

Forbidden Modifications:
globals.css Override
Page-Level Styling
03 — LIVE COMPONENT DOCUMENTATION RULE

Whenever a component becomes:

Live / Current Production

a registry file must be created.

Location:

docs/design-system/components/

Example:

project-card.md
project-hero.md
section-navigator.md

No production component may exist without documentation.

04 — TOKEN REGISTRY RULE

Every semantic token must have:

Token:
Category:
Value:
Inherited From:
Used By:

Example:

Token:
text-secondary

Category:
Semantic

Value:
#6B6C72

Inherited From:
neutral-500

Used By:
ProjectCard
Navigator
SummaryCard

Purpose:

Allow AI to understand impact before modification.

05 — TOKEN TRACEABILITY RULE

All semantic tokens must be traceable.

Required chain:

Primitive
↓
Semantic
↓
Component Token
↓
Component
↓
Usage

Example:

#6B6C72
↓
neutral-500
↓
text-secondary
↓
card-meta-text
↓
ProjectCard
↓
Work Page

AI must be able to identify the entire dependency chain.

06 — USAGE REGISTRY RULE

Every reusable component must declare usage scope.

Example:

Component:
SectionNavigator

Used In:
/work/dbs-exception-management
/work/voucher-incentive-ecosystem

Not Used In:
Homepage
Results

Purpose:

Prevent accidental global regressions.

07 — FIGMA MAPPING RULE

Every reusable component must map back to a Figma source.

Required fields:

Figma File:
Node ID:
Frame Name:

Example:

Component:
ProjectHero

Figma File:
Portfolio Website

Node ID:
2191-545

Frame:
Project Hero

AI must never guess which Figma frame owns a component.

08 — COMPONENT OWNERSHIP REGISTRY RULE

Registry is the source of truth for ownership.

AI must consult:

React Source
CSS Owner
Token Dependencies

before modifying UI.

Forbidden:

Guessing component ownership
Guessing CSS ownership
Guessing token ownership
09 — AI CONTEXT GENERATION RULE

Registry files must be structured so they can be automatically converted into:

AI Context
MCP Context
Code Connect Metadata
Design System Explorer

Documentation is not only for humans.

Documentation must be machine-readable.

10 — DESIGN SYSTEM EXPLORER RULE

The future Design System page must be generated from Registry data.

Forbidden:

Manual Design System Showcase

Allowed:

Registry
↓
Explorer

The visual design system must always reflect the real codebase.

11 — PORTFOLIO DIFFERENTIATION RULE

The Design System is not a UI library showcase.

It is a:

Human + AI Design System Operating System

The portfolio must demonstrate:

Component Governance
Token Governance
Ownership Architecture
Figma Mapping
AI Collaboration Readiness

instead of only colors, typography, and buttons.

12 — IMPLEMENTATION PRIORITY RULE

Priority order:

1. Stabilize Production UI

2. Build Component Registry

3. Build Token Registry

4. Build Usage Registry

5. Build Figma Mapping Registry

6. Build AI Context Layer

7. Build Design System Explorer

Never reverse this order.

The registry layer is required before the explorer layer.

13 — AI EXECUTION RULE (CRITICAL)

Before modifying any reusable component:

AI must identify:

Component Owner
CSS Owner
Token Dependencies
Usage Scope
Figma Mapping

If any item is unknown:

STOP
AUDIT
UPDATE REGISTRY
THEN MODIFY

Never modify reusable UI based on assumptions.
