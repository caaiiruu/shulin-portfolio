## QA Screenshot Cleanup Rule

After each screenshot-based QA cycle has been reviewed, the generated screenshot files must be cleaned up before starting the next QA cycle.

### Core rule

Do not keep accumulating old QA screenshots, screenshot zip files, or temporary visual QA artifacts inside the repo.

Each QA cycle should produce a fresh screenshot set only for the current review.

### Required cleanup flow

Before generating a new screenshot QA package:

1. Confirm the previous screenshots have already been reviewed.
2. Delete the previous QA screenshot folder and zip file for that step.
3. Recreate a clean screenshots folder.
4. Generate the new screenshots.
5. Zip only the new screenshots.
6. Reveal the new zip file in Finder using:
   `open -R <zip-path>`

### Required terminal pattern

Use this pattern before a new visual QA capture:

```bash
rm -rf <qa-folder>/screenshots
rm -f <qa-folder>/screenshots.zip
mkdir -p <qa-folder>/screenshots

Then after screenshots are generated:

zip -r <qa-folder>/screenshots.zip <qa-folder>/screenshots
open -R <qa-folder>/screenshots.zip
Safety rules
Do not delete screenshots before they have been reviewed.
Do not delete source files, component files, CSS files, or audit reports when cleaning screenshots.
Only delete:
<qa-folder>/screenshots
<qa-folder>/screenshots.zip
Do not delete .next, node_modules, or build output as part of visual QA cleanup.
Do not reuse screenshots from an old failed QA cycle for a new decision.
Purpose

This keeps the repo clean, avoids uploading outdated screenshots, reduces storage bloat, and ensures every visual QA decision is based only on the latest build state.
