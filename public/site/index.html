      Design principles

      Four decisions I repeat.

      A compact operating model for systems, decisions, real use, and scale.

      01

      Model the system before the screen.

      Define roles, states, rules, and ownership before interface structure.

      What it changesOne shared operating model
      02

      Make blocked states and next actions visible.

      Show priority, consequence, fallback, and what happens next.

      What it changesFaster, defensible decisions
      03

      Start from analogous behaviour. Refine in use.

      Borrow the logic behind comparable behaviour, then learn from hesitation, failure, and recovery.

      What it changesA grounded 0→1 product before patterns exist
      04

      Build reusable capability—not repeated screens.

      Separate product logic from presentation so the model can scale.

      What it changesScalable product capability
